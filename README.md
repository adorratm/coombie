# Survivor-like Cursor AI Development Pack

A repository-aware AI workflow for an existing, playable survivor-like game targeting PC/Steam.

## Important project-specific constraint
The game engine and programming language are intentionally **not assumed**. The first task is to inspect the repository and record the actual stack. Do not introduce Unity, Unreal, Godot, C#, C++, or another framework unless the repository proves it is used.

## Installation
1. Extract this archive into the **root of your game repository**.
2. Keep or merge any existing `.cursor` files; do not overwrite your existing rules, agents, or skills blindly.
3. Open the repository in Cursor.
4. Start a new Agent conversation and run the bootstrap prompt in `prompts/00-repository-audit.md`.
5. Review `docs/PROJECT_PROFILE.md` generated by the audit. Correct any assumptions.
6. Invoke skills with `/skill-name`, or ask Agent to use them. Custom subagents are in `.cursor/agents/`.

## Pack contents
- `.cursor/rules/`: always-on project guardrails
- `.cursor/skills/`: repeatable specialist workflows
- `.cursor/agents/`: focused subagents
- `prompts/`: ready-to-paste tasks
- `docs/`: project profile template, design and verification standards

## Recommended workflow
1. Audit before editing.
2. Plan one vertical slice at a time.
3. Implement the smallest complete change.
4. Run build/tests and a real game smoke test where possible.
5. Ask `/gameplay-qa` or `/performance-auditor` for independent verification.
6. Record decisions and update the project profile.

## Safety
- Commit or create a checkpoint before substantial AI edits.
- Do not allow broad rewrites of working systems.
- Do not let multiple agents edit the same files concurrently unless their work is isolated.
- Never claim a feature works solely because code was generated or compilation passed.
